## 1. الملخص التنفيذي

MenaFlow منتج ناضج هندسيًا أكثر من كونه «نموذجًا أوليًا»: عقد API مولّد (OpenAPI → Zod → React Query)، 86 مسارًا، 35 ترحيل SQL، عزل مساحات عمل عبر `x-workspace-id` + عضوية، تشفير رموز Meta ورسائل واتساب الخاصة، ويبهوكس موقّعة (HMAC)، وطوابير عمل مع أقفال (leases) لمنع الردود المكررة، و377 اختبارًا تمر جميعها، وCI يبني الخادم.

الفجوة الحقيقية ليست «جودة الكود» بل **قابلية البيع**: لا بوابة دفع (`paymentAvailable: false`)، لا قناة إشعارات للمستخدم (لا Push ولا بريد)، لا حذف/تصدير لمساحة عمل، وصلاحيات الأدوار لا تُطبَّق إلا في موضعين، وتخزين الوسائط على **قرص الخادم** لا على تخزين كائنات — وهو ما ينكسر عند التوسّع الأفقي أو النشر بلا قرص دائم.

**الحكم:** جاهز لاستخدام داخلي/تجريبي مدفوع بجهد يدوي؛ **غير جاهز لاستقبال عملاء يدفعون** قبل إغلاق P0 (الدفع، الإشعارات، التخزين، الأدوار، حذف/تصدير).

### أبرز القوى
- عقد واحد مشترك ومنع الانحراف بين الواجهة والخادم.
- أمان أساسي صحيح: HMAC للويبهوكس، روابط وسائط موقّعة بانتهاء صلاحية، تشفير مع دعم مفتاح سابق للتدوير، حدود معدل.
- تدفق رد آلي مصمّم بوعي: طابور + قفل حدث + منع التكرار + سقف حصة AI.
- نظافة كود: 0 `console.log` في الخادم، 0 `TODO/FIXME`، 3 تجاوزات TypeScript فقط.

### أبرز المخاطر
| # | الخطر | الأثر |
|---|---|---|
| 1 | لا بوابة دفع | لا يمكن تحصيل أي مبلغ |
| 2 | وسائط على قرص محلي | فقدان ملفات عند إعادة نشر/توسّع أفقي |
| 3 | صلاحيات بالأدوار غير مطبّقة | أي عضو يستطيع فصل قناة أو حذف بيانات |
| 4 | لا إشعارات | الطلبات والمراجعات وتعرّض النشر لا تصل للمستخدم |
| 5 | لا حذف/تصدير لمساحة العمل | التزامات قانونية (حقوق البيانات) غير مغطاة |
| 6 | لا رصد أخطاء (Sentry/OTel) | اكتشاف الأعطال بالشكوى لا بالمراقبة |

## 4. العمارة — التقييم والتوصيات

**الحالة الفعلية (متحقّق منها):**
```
mobile (Expo) ──> api-client-react ──> api-zod
api-server ──> api-zod
api-server ──> db (Drizzle + pg pool)
api-spec ──> يولّد api-client-react + api-zod
```
- الخادم: `src/app.ts` (helmet, cors, rate limits, clerk middleware, pino) → `routes/index.ts` (37 موجّهًا).
- العمّال: ردود آلية، تأكيد طلبات، احتفاظ رسائل، اشتراكات ويبهوك Meta، استخراج منتجات، نشر، تنزيل وسائط — تُشغَّل داخل عملية API، ولها أمر عامل منفصل.

**توصيات (بأثر قابل للقياس):**
1. **تخزين الوسائط**: واجهة `MediaStore` (put/get/signedUrl) بمزوّدين: قرص (تطوير) وكائنات (إنتاج). الأثر: إزالة نقطة فشل واحدة وإتاحة أكثر من نسخة.
2. **التفويض**: طبقة `requireWorkspaceRole` + مصفوفة صلاحيات مركزية؛ الأثر: تقليل سطح الهجوم الإداري، وتلبية متطلبات فرق العمل.
3. **العقود**: توليد المسارات من OpenAPI (أو تحقق `api-zod` على المدخلات إلزاميًا)؛ الأثر: منع انحراف المدخلات وتقليل أخطاء 500.
4. **العمّال**: فصل اختياري عبر متغير بيئة واحد (موجود فعليًا) + وثيقة «وضعان: مدمج/منفصل».
5. **الترحيلات**: `drizzle generate` + بوابة CI تقارن المخطط بالسحابة.
6. **المراقبة**: Sentry (خادم + واجهة) + لوحة مقاييس (زمن المسارات، فشل الطوابير، عمر الرسائل المعلّقة).

## 9. ما لم أتحقق منه (صريحًا)

1. **بيئة الإنتاج الفعلية**: لا وصول إلى Vercel أو Supabase أو Evolution أو قاعدة بيانات الإنتاج؛ كل ما يخص الترحيلات/النسخ الاحتياطي مبني على المستودع والتوثيق.
2. **تغطية اختبارات فعلية**: 377 اختبارًا تمر، لكن لم أقِس التغطية (%) ولم أتحقق من تغطية المسارات الحرجة عدديًا.
3. **`pnpm run typecheck` الجذري**: فشل في هذه البيئة لأن الأمر الفرعي لا يجد `pnpm` في `PATH` (`sh: 1: pnpm: not found`)، وليس لعيب في الكود؛ تحققت بدلًا منه:
   - `pnpm run typecheck:libs` ✅
   - `pnpm -r --filter "./artifacts/**" --filter "./scripts" run typecheck` ✅ (4 حزم)
   - `pnpm --filter @workspace/menaflow-mobile run typecheck` ✅ (مسبقًا في هذه الجلسة)
4. **Node**: البيئة الحالية `v22.22.3` بينما CI يستخدم Node 24 — لم أختبر التوافق على 24 محليًا.
5. **متجر التطبيقات**: لم أختبر بناء iOS/Android فعليًا؛ التحقق شمل typecheck فقط.
6. **النصوص القانونية وSEO**: لم أفحص محتوى صفحات الخصوصية/الشروط.
7. **سلامة وسائط المستخدم**: لا فحص لسلامة الملفات المرفوعة (لا يوجد رفع متعدد الأجزاء حاليًا).
